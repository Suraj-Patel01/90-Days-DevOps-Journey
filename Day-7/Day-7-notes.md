# Part 1: Linux File System Hierarchy

## `/` – Root

The `/` directory is the starting point of the Linux file system. All files and directories exist under the root directory.

```bash
ls -l /
```

**I would use this when:** I need to understand the main structure of a Linux system.

---

## `/home` – User Home Directories

Contains the personal directories and files of normal users.

```bash
ls -l /home
```

**I would use this when:** I need to access or manage user files.

---

## `/root` – Root User's Home

The home directory of the root user.

```bash
ls -l /root
```

**I would use this when:** I need to access files belonging to the root user.

---

## `/etc` – Configuration Files

Contains system and application configuration files.

```bash
ls -l /etc
```

Example files/directories:

```text
hostname
ssh/
```

**I would use this when:** I need to check or modify system configuration.

---

## `/var/log` – Log Files

Contains logs generated by the operating system and applications. This is very important for troubleshooting.

```bash
ls -l /var/log
```

Example:

```text
syslog
auth.log
```

**I would use this when:** I need to investigate errors or system activity.

---

## `/tmp` – Temporary Files

Used for temporary files created by applications and users.

```bash
ls -l /tmp
```

**I would use this when:** I need temporary storage for testing or troubleshooting.

---

## `/bin` – Essential Commands

Contains essential command binaries used by the system.

```bash
ls -l /bin
```

**I would use this when:** I need to locate essential Linux commands.

---

## `/usr/bin` – User Commands

Contains many executable programs and user commands.

```bash
ls -l /usr/bin
```

**I would use this when:** I need to find installed command-line utilities.

---

## `/opt` – Optional Applications

Used for optional or third-party software installations.

```bash
ls -l /opt
```

**I would use this when:** I need to manage manually installed or third-party applications.

---

# Hands-on File System Checks

## Find Large Log Files

```bash
du -sh /var/log/* 2>/dev/null | sort -h | tail -5
```

**Observation:** Displays the largest files and directories inside `/var/log`.

---

## Check Hostname Configuration

```bash
cat /etc/hostname
```

**Observation:** Displays the hostname configured for the system.

---

## Check Home Directory

```bash
ls -la ~
```

**Observation:** Displays files and hidden files inside my home directory.

# Part 2: Scenario-Based Practice

## Solved Example: Check if a Service is Running

### Step 1: Check Service Status

```bash
systemctl status nginx
```

**Why:** Shows whether the service is active, failed, or stopped.

### Step 2: List Services

```bash
systemctl list-units --type=service
```

**Why:** Helps identify services currently loaded on the system.

### Step 3: Check if Service Starts at Boot

```bash
systemctl is-enabled nginx
```

**Why:** Shows whether the service is configured to start automatically after boot.

### What I Learned

Always check the service status first and then investigate logs and configuration based on the result.

---

# Scenario 1: Service Not Starting

**Problem:** A web application called `myapp` failed to start after a server reboot.

### Step 1

```bash
systemctl status myapp
```

**Why:** Checks whether the service is failed or inactive and may show the immediate error.

### Step 2

```bash
journalctl -u myapp -n 50
```

**Why:** Shows recent logs from the service to identify the cause.

### Step 3

```bash
systemctl is-enabled myapp
```

**Why:** Checks whether the service is enabled to start automatically at boot.

### Step 4

```bash
systemctl restart myapp
```

**Why:** Attempts to restart the service after identifying or correcting the issue.

---

# Scenario 2: High CPU Usage

**Problem:** The application server is slow and a process may be consuming too much CPU.

### Step 1

```bash
top
```

**Why:** Shows live CPU usage and helps identify processes consuming high CPU.

### Step 2

```bash
ps aux --sort=-%cpu | head -10
```

**Why:** Displays processes sorted by CPU usage.

### Step 3

```bash
ps -p <PID> -f
```

**Why:** Shows detailed information about the process identified by its PID.

### What I Learned

I should identify the process and collect evidence before stopping or killing it.

---

# Scenario 3: Finding Service Logs

**Problem:** A developer asks where the logs for a systemd-managed service are located.

### Step 1: Check Service Status

```bash
systemctl status ssh
```

**Why:** Confirms the service status and may show recent log entries.

### Step 2: View Last 50 Logs

```bash
journalctl -u ssh -n 50
```

**Why:** Displays the latest 50 log entries for the SSH service.

### Step 3: Follow Logs in Real Time

```bash
journalctl -u ssh -f
```

**Why:** Continuously displays new log entries as they are generated.

### What I Learned

Systemd services commonly use `journald`, and `journalctl -u <service>` is useful for troubleshooting them.

---

# Scenario 4: File Permissions Issue

**Problem:** A script cannot be executed because of a permission error.

### Step 1: Check Permissions

```bash
ls -l /home/user/backup.sh
```

**Why:** Checks whether the file has execute permission.

Example:

```text
-rw-r--r--
```

There is no `x` permission, so the file cannot be executed directly.

### Step 2: Add Execute Permission

```bash
chmod +x /home/user/backup.sh
```

**Why:** Adds execute permission to the script.

### Step 3: Verify Permissions

```bash
ls -l /home/user/backup.sh
```

Expected:

```text
-rwxr-xr-x
```

### Step 4: Run the Script

```bash
./backup.sh
```

**Why:** Executes the script after the required permission has been added.
